  entitlement review belong to the distribution phase, not this spike.
- Codex CLI 0.146.0 is the minimum tested version for the spike. Compatibility
  is also capability-probed, so version alone never marks an installation as
  ready.
- Project movement is supported while the project is closed. Moving a live,
  open SQLite bundle is explicitly out of scope.
- Phase 1 pins nothing new: same toolchain, GRDB, swift-json-schema, and CI
  runner as Phase 0. `FilmScript` (parser) and `ScreenplaySamples` are new
  targets inside the FilmCore package; `FilmEval` and `filmcamp-eval` are new
  targets inside the FilmBrain package. No new external dependency is added
  in Phase 1.
- Codex CLI 0.146.0 remains the minimum. The Phase 1 invocation adds config
  overrides verified on 0.147.0; unknown keys are ignored by older versions.
- Sample screenplays are original synthetic works written for this repo. No
  commercial or third-party screenplay text is committed (see design §12.1).
- Phase 3 pins nothing new: same toolchain, GRDB, swift-json-schema, and CI runner; no new
  external dependency, no provider SDK, no network path, and no credential storage of any
  kind. The one build-description change is `PromptSkills/` joining the app target as a
  folder resource (vendored payload, never app code); the assumption that Codex's read-only
  sandbox permits reads outside the workspace is **probed, not pinned** — Plan 016 carries
  both materialiser designs and one live request settles it. The `assets.status` CHECK
  already admits all seven states, so Phase 3 activates `prompt_ready`/`in_progress` with no
  vocabulary change.
- Phase 4 pins nothing new: same toolchain, GRDB, swift-json-schema, and CI runner; no new
  external dependency, no provider, no network path beyond the existing Codex harness, and
  **no migration** — bundle schema stays 5, no table or column is added, and the
  recommendation report rides the existing task-gated `jobs.apply_report_json` column. The
  one navigation-model change is the `.dashboard` `ProjectSection` case. Scene readiness is
  derived at read time, never stored.
- Phase 5 pins nothing new externally: same toolchain, GRDB, swift-json-schema, and CI
  runner; no new dependency, no provider, no network path beyond the existing Codex
  harness. It **does** carry the first migration since v5 — bundle schema 6 adds
  `scene_prompts`, `scene_prompt_references`, `imported_skills`, and three `projects`
  columns, additive only. The one navigation-model change is the `.generation`
  `ProjectSection` case. Package states are derived at read time against the persisted
  active target profile, never stored; exports are derived artifacts written inside the
  bundle under `exports/scenes/`, staged, hash-verified, and atomically replaced. The
  target-profile catalog is Film-Camp-authored; the vendored
  `PromptSkills/higgsfield/specs/model-specs.json` is read by tests only, never by app
  code at runtime, and `seedance_lint.py` is the operator's acceptance-time preflight,
  never an app gate (§14.3).
- The four source snapshots live in the sibling
  `../aifilmcamp-app-references/` directory. They are advisory and are not
  dependencies by default. Because the snapshots have no Git metadata, any
  implementation based on them must check upstream and record the upstream
  version or commit used.

## Findings considered and rejected

- **Build the Phase 1 ontology now:** rejected because Phase 0 exists to prove
  infrastructure, while deterministic parsing, provenance, editing, merging,
  and locking are explicitly assigned to Phase 1.
- **Use a direct OpenAI API integration:** rejected because the product docs
  make the user's locally authenticated Codex CLI the primary hard requirement.
- **Add Claude Code, Grok Build, MCP, or multi-agent sessions:** rejected for
  Phase 0. The adapter seam is included, but only the Codex batch path is built.
- **Copy one reference application's architecture wholesale:** rejected. Use
  the task-oriented seams in `docs/REFERENCE_PROJECTS.md`; FilmBrain and
  FilmCore remain the product's architectural boundary.
- **Adopt a document-framework rewrite before proving storage:** rejected. The
  spike uses a small package service plus AppKit open/save panels and Finder
  open-event handling; a richer `NSDocument` architecture should be justified
  by later editing and autosave requirements.
- **Ship an integrated image-generation provider in Phase 3:** rejected at the time
  (design §3.6, §14.3 — owner-decided 2026-08-22), then **narrowly reversed by the
  product owner on 2026-08-26 in Plan 024** for still-image reference creation through
  a local executable. Plan 025 supersedes only that provider adapter on 2026-08-28:
  reference images use direct Google and OpenAI APIs through a bundled helper, with
  user-supplied keys held in macOS Keychain. The 2026-09-01 owner amendment now
  permits direct generated video through provider-neutral integrations in Phase
  5d (Plan 032), beginning with Higgsfield; editing, rendering, a hosted gateway,
  and general-purpose credential handling remain excluded.
- **Adopt the vendored `seedance_lint.py` as the prompt validator:** rejected
  (design §3.5, §13.7). Its specs hold no image model, and its
  scene-completeness warnings misfire on grey-background reference sheets;
  Phase 3's semantic validator is Film-Camp-authored, and the linter is scoped
  to Phase 5's video prompts.
- **Store prompt staleness as a flag or status:** rejected (design §3.4). It is
  a derived digest comparison over §8.2's rendered input — no fan-out triggers,
  no clearing gesture, no way for flag and truth to disagree.
- **Version prompts as many live rows with a selection gesture:** rejected
  (design §3.2). One current prompt per requirement, history by number;
  delete-the-newest is the restore gesture.
- **Widen `canReplaceScreenplay` for prompt rows:** rejected (design §7.3).
  Active prompt-bearing slots are already doubly behind the built gate, and an
  unqualified widening would let hidden tombstoned prompt history refuse
  Replace forever.
- **Gate the workshop on a dedicated window or a third split column:** rejected
  (design §5.1). The built shell has one window model per bundle and two
  columns; the workshop is an in-content master–detail in the Manifest section,
  which is also what Phase 4's deep link needs.
- **Editable per-edge role/exclusion/fidelity metadata:** rejected by owner
  decision 2026-08-22 (design §3.3, §13.6). All three derive at render time
  from pinned rules and are recorded immutably on citation rows; the vendored
  README says the mapping can be emitted mechanically, and the editable
  machinery was where review defects concentrated. Per-edge overrides remain
  an additive seam (design §11).
